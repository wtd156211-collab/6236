# 多租户文件网关的路径规范化

我们做多租户的文件网关，用户请求里带路径，服务端拼到自己根目录下面去取文件。上线前的安全评审被指出一堆问题：点点斜杠能不能穿越、保留设备名、大小写不敏感的文件系统、还有超长路径。我打算把这块单独写成一个库。

规则写在下面：相对路径怎么解析成绝对路径、哪些段要折叠、大小写按什么口径比、保留名怎么判、盘符和网络路径前缀怎么处理，以及**拼完之后必须落在根目录里面**这条硬约束。规范化必须**幂等**：规范化过的路径再规范化一次结果不变。越界检测要给准确结论——允许的返回规范化结果，越界的拒绝并**说清楚是走到哪一段才越界的**。边角也要照顾到：超长路径、只有分隔符、空段、末尾是分隔符、路径里有看着像通配符的字符。性能上单次规范化要在微秒级，别每次都重新做一遍字符串拼接和切分。实现只用标准库，测试用 unittest。

仓库里只有这份说明和 samples 里的用例，代码从零写。

## 规则表

| 项 | 口径 |
| --- | --- |
| 分隔符 | `/` 与 `\` 都算分隔符，输出统一用 `/` |
| 绝对路径 | 以 `/` 或 `\` 开头（含「只有分隔符」）一律拒绝：`ABSOLUTE_PATH` |
| 盘符前缀 | 形如 `C:` 的单字母加冒号前缀，拒绝：`ABSOLUTE_PATH` |
| 网络路径 | `\\` 开头的 UNC 前缀，拒绝：`ABSOLUTE_PATH` |
| 空段 | 连续分隔符产生的空段直接丢弃 |
| `.` 段 | 丢弃（当前目录） |
| `..` 段 | 弹出上一层；**已经在根上再弹就是越界**：`ESCAPE` |
| 末尾分隔符 | 丢弃，`logs/2026/` 与 `logs/2026` 等价 |
| 大小写 | 比较时**不区分大小写**（按 ASCII 小写比）；输出**保留请求里的原始大小写**，不转换 |
| 保留设备名 | 段的**主干**（第一个点之前的部分，大小写不敏感）等于 `CON`/`PRN`/`AUX`/`NUL`/`COM1`–`COM9`/`LPT1`–`LPT9` 就拒绝：`RESERVED_NAME`（`con`、`LPT1.txt`、`Aux.cfg` 都算） |
| 非法字符 | ASCII 控制字符（`0x00`–`0x1F`）与 `* ? " < > \| :` 一律拒绝：`BAD_CHARS` |
| 普通字符 | `[`、`]`、`#`、`%`、`~`、`+`、`&` 等都是普通字符；**本库不做通配符展开**，`[2026]` 就是字面目录名 |
| 长度 | 单段超过 `max_segment_len`（默认 255）或整条绝对路径超过 `max_path_len`（默认 260）都拒绝：`TOO_LONG` |
| 硬约束 | 拼接后的绝对路径必须**以根目录为前缀**（按段比较、不区分大小写），否则 `ESCAPE` |

空请求（空字符串）与「折叠后回到根」的请求是允许的，结果就是根目录本身。

## 幂等口径

把规范化结果去掉根前缀、当成新的请求再规范化一次，结果必须与原结果**完全相同**（包括大小写与分隔符）；这条要有测试证明，样例里也顺手验了一遍。

## 输出格式

每条用例输出一行，逗号分隔，行尾 LF：

```text
<用例编号>,ok,<规范化后的绝对路径>
<用例编号>,error,<原因码>,<段序号>,<detail>
```

- **段序号**是出问题的段在**原始请求按分隔符切分后**的位置（从 1 开始，空段也算一个位置）；整体性问题（绝对路径、整条超长）写 `0`；
- `detail` 里不含逗号，形如 `segment=..`、`name=LPT1.txt`、`char=*`、`char=0x01`、`path_len=306`、`segment_len=304`、`prefix=C:`。

## 拒绝原因码

| 原因码 | 什么时候报 | 段序号 |
| --- | --- | --- |
| `ABSOLUTE_PATH` | 以分隔符开头、盘符前缀、UNC 前缀 | `0` |
| `ESCAPE` | `..` 退到根之上；或拼出来的路径不在根目录内 | 越界的那一段；整体性问题写 `0` |
| `RESERVED_NAME` | 段的主干是保留设备名 | 该段 |
| `BAD_CHARS` | 段里出现控制字符或非法字符 | 该段 |
| `TOO_LONG` | 单段超长（`segment_len=`）或整条超长（`path_len=`） | 超长的那一段；整条超长写 `0` |

## 性能要求

- 单次规范化在**微秒级**（本机百万次规范化不超过几秒）；
- 实现要**单遍扫描**：一次切段、一次拼接，别在循环里反复 `split`/`join`/字符串相加；允许缓存根目录的解析结果（段数组、长度），但缓存不能改变结果；
- 同一份输入跑两遍结果必须逐字节一样。

## 样例

```text
samples/cases.json     28 条用例：编号、说明、根目录、请求路径
samples/expected.txt   对应的期望结果（12 条允许 + 16 条拒绝）
```

覆盖的边角：反斜杠分隔符、`.` 与重复分隔符、末尾分隔符、只有分隔符、空请求、折叠后回到根、`..` 恰好不越界与越界到第几段、保留设备名（`con`、`LPT1.txt`、`Aux.cfg`）、非法字符（`*`、`?`、`:`、控制字符）、单段超长与整条超长、看着像通配符的 `[2026]`、大小写混合、根目录自带末尾分隔符。

## 使用

```python
from pathnorm import normalize, PathRejected

try:
    path = normalize("/srv/tenants/acme", "reports/2026/q3.csv")
except PathRejected as exc:
    log(exc.code, exc.segment, exc.detail)   # 原因码、段序号、detail
```

- `normalize(root, request, max_segment_len=255, max_path_len=260)`：成功返回规范化后的绝对路径，失败抛 `PathRejected`；
- `python3 run_samples.py`：逐条跑 `samples/cases.json`，输出格式与 `samples/expected.txt` 一致；
- `python3 -m unittest`：规则单测 + 样例对照 + 幂等性 + 性能冒烟。

## 实现说明

**单遍扫描**：`normalize` 对请求串只做一次 `re.split(r"[/\\]")` 切分，然后逐个段走一遍循环：空段和 `.` 丢弃，`..` 弹栈，其余段依次做非法字符（一个预编译正则）、保留名（`frozenset` 查表）、单段长度三项检查，通过后压入 `kept` 栈。整条路径的长度随循环累计（每段贡献 `1 + len(seg)`，弹栈时减回），不在循环里做任何字符串拼接；最后只做一次 `"/".join(kept)` 拼出结果。

**根目录缓存**：`_parse_root` 用 `functools.lru_cache`（上限 256 个根）缓存每个根目录的解析结果，含三样：折叠后的展示串 `display`（输出直接以它为前缀）、按段 ASCII 小写后的段元组（硬约束的按段比较用）、根与第一段之间的连接符。缓存是 root 字符串的纯函数，不改变任何结果；同一份输入跑两遍逐字节相同。

**段序号怎么数**：请求串按单个分隔符切分（`/` 和 `\\` 都算），切出来的每一项——包括连续分隔符产生的空串——都占一个位置，从 1 开始数。循环里用 `enumerate(..., 1)` 拿到这个序号，所以 `a//../..` 越界报的是第 4 段（切分结果是 `['a', '', '..', '..']`）。整体性问题（绝对路径前缀、整条超长、硬约束兜底）没有对应段，写 0。

**幂等**：输出只由「根目录展示串 + 保留下来的原始段」组成，段里不含分隔符、`.`/`..`、非法字符、保留名和超长段，大小写原样保留；把输出去掉根前缀再喂给 `normalize`，每一段都原样通过同一套检查，结果必然逐字节相同。`test_pathnorm.py` 里对 12 条允许样例和一组折叠用例都做了「规范化两次结果相同」的断言。

**性能**：本机实测单次规范化约 1µs（2 万次混合请求耗时 0.022s），量级在微秒级；热路径上只有一次切分、每段一次正则查找和一次 `frozenset` 命中，没有重复 `split`/`join`/字符串相加。
